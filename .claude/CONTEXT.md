# CrossPoint Reader — Durable Context

Keep this file focused on repo-specific gotchas that are worth reusing in future sessions.

## FreeInk SDK

Refer to https://freeink.org/llms.txt for guidance.

## Simulator

- Simulator patches belong in the adjacent `crossink-simulator` repo.
- The valid local simulator env in this repo is `simulator`, and `pio run -e simulator` currently builds cleanly.
- The simulator `PNGdec` stub in `crossink-simulator/src/PNGdec.h` needs to mirror the real API shape used by app code, including `hasAlpha()` and `getTransparentColor()`, even though decode still fails intentionally.
- Known simulator limits:
  - No image rendering: `platformio.ini` ignores `hal`, `PNGdec`, and `JPEGDEC`, so image decoders are intentionally absent.
  - JPEGDEC stub always fails; `JPEGDEC fallback: open failed (err=-1)` is expected in simulator.
  - `esp_deep_sleep_start()` is a no-op in simulator.
  - `HalStorage` uses POSIX file access under `./fs_` and allows multiple readers, unlike real hardware.
- Headless screenshots: `CROSSPOINT_SIM_SCREENSHOTS="<ms>:<path.bmp>;..."` saves the SDL renderer
  output. It needs `SDL_VIDEODRIVER=offscreen`; with `dummy` the capture silently saves nothing.
- Seeding Home recents for a capture: the live store is JSON at `/.crosspoint/recent.json`
  (`RecentBooksStore::getFilePath()`), while `/.crosspoint/recent.bin` is a legacy **binary** format
  (writing JSON there logs `Deserialization failed: Unknown version 123`). Keys are
  `books[].{path,title,author,coverBmpPath,coverState}`; every `path` must exist on the card, and
  `HomeActivity::loadRecentBooks` skips entries where `RecentBooksStore::isMissing(book)` is true, so
  do not seed `coverState: Missing` unless the empty state is what you want to see.
- Startup theme, scale and language for a capture come from `/.crosspoint/crossink-settings.json`
  (for example `{"uiTheme": 9, "language": "VI"}`); the smoke test's env vars only cover themes.

## Real Hardware / Storage

- SdFat on hardware allows only one open reader per file path at a time. If a fallback needs to reopen the same file, close the first handle before reopening.

## Rendering / Reader Pipeline

- `lib/Epub/Epub/Page.cpp`: images must render only in `GfxRenderer::BW`; grayscale passes are text anti-aliasing passes only.
- Kindle EPUBs may contain paired high-res and old-Kindle fallback images. `ChapterHtmlSlimParser` should skip `<img>` nodes with `data-AmznRemoved-M8` to avoid duplicate stacked images.
- After image/layout pipeline changes that affect cached EPUB output, clear the affected `.crosspoint/epub_<hash>/` cache if behavior looks stale.

## UI Consistency

- Use FreeInkUI SDK components and input routing for list-style screens where possible. Row rendering, touch targets,
  hit testing, and pagination should share the same FreeInkUI list configuration instead of custom touch scaling.

## UI Themes

- Adding a theme touches `CrossPointSettings.h` (`UI_THEME`, append only — raw values are persisted),
  `UITheme.cpp` `setTheme`, `SettingsList.cpp` (labels plus `withEnumRawValues`),
  `ButtonRemapActivity::usesLyraValueBadge` for Lyra-derived themes, the theme-name keys in
  `lib/I18n/translations/*.yaml`, `SimulatorSmokeTest.cpp`'s home-theme regression list, and the
  `THEMES` map in `scripts/run_simulator_smoke_test.py`.
- A Home-only theme still needs its own `HomeActivity::render()` and `loop()` branches; `ThemeMetrics`
  cannot remove the always-visible Home menu rows by itself.
- Home covers are 2:3. `UITheme::getCoverThumbPath(path, height)` generates that ratio and `LyraTheme`
  sizes its cover to match; there is no `drawBitmapStretched` in `GfxRenderer`.

## Heap Baselines (X4 hardware, SD card font)

- A normal resume-into-partial reading session runs at ~85-90KB free / ~49KB maxAlloc by
  the first watermark crossing (Epub metadata + x-locations + resident glyph caches).
  Do not read mid-range heap numbers as session degradation without checking the scenario.
- SD-font section builds cost ~38-50KB at cold start; the 4-style advance-table prewarm
  (~30KB incl. 16KB contiguous scratch) dominates and is skipped below 80KB free.

## Localization (I18n)

- Edit `lib/I18n/translations/*.yaml` only. `I18nKeys.h` and `I18nStrings.{h,cpp}` are generated by
  `scripts/gen_i18n.py` and gitignored; a build regenerates them.
- `I18nStrings.cpp` stores each language as one NUL-separated blob of concatenated literals with
  non-ASCII written as `\xNN` escapes, so grepping the generated file for a translated string finds
  nothing. Grep the YAML key instead, or decode the blob.
- The generator drops entries whose text equals English, so language tables have different lengths and
  indices. Do not compare indices across languages.
- A key missing from a locale falls back to English, so a partially translated file is expected and
  cannot be distinguished from a correct English value at runtime.

## Lunar Calendar Engine

- The `newMoon()` series in `lib/LunarCalendar/LunarCalendar.cpp` uses Jean Meeus Table 49.A
  (25 periodic terms + E eccentricity + Omega). An earlier version used Ho Ngoc Duc's abridged
  13-term series, which mis-assigned the Vietnamese 2023 leap month to tháng Giêng (month 1)
  instead of the correct tháng Hai (month 2, running 22/03–19/04/2023). The root cause was
  insufficient new-moon accuracy near the midnight boundary: the true new moon on 2023-03-21
  17:24 UTC falls at 22/03 00:24 ICT, only 24 minutes past local midnight.
- Never "fix" a lunar test failure by copying engine output into test expectations. Always
  cross-check against a published Vietnamese lịch vạn niên or an independent astronomical
  reference (e.g. PyMeeus, USNO).

## Misc Repo Gotchas

- POSIX TZ signs are inverted from ISO 8601 in `TimeStore::applyTimezone()`: `"UTC-1"` means UTC+1.
- `LyraTheme::drawHeader()` does not call `BaseTheme::drawHeader()`, so header changes in the base theme must be duplicated in Lyra if needed.
